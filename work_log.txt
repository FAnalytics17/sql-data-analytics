Lessons learned
Always check whether a join multiplies rows (several visits per source, several territories per employee). Filters like visit_count = 1 prevent double counting.
NULL comparisons are never true, so rows with missing values can quietly drop out of a WHERE clause.
Filter the subquery and the outer query to the same year when comparing against an average.
Prefix columns with table aliases to keep queries clear as schemas grow.
Views and CTEs make later analysis simpler by avoiding repeated joins.
Check an INSERT ... SELECT for column order and run it only once, or rows will be duplicated.
